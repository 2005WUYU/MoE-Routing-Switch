# 工程问题的三步实验链

更新：2026-09-06。当前入口是 `python -m moe_study.engineering`。这一版复用训练、优化器恢复、数据、EP 和精度参考接口，修改比较、采样、统计和报告；不需要推倒训练底座。

研究顺序按用户的原始问题执行：

1. 实际 optimizer 步长下，换路由是否造成足以抵消这一步连续收益的任务损害。
2. 相同位置、相同表示、相同扰动范数下，真实路由方向是否比普通随机方向更危险。
3. 用独立的配对训练实验检验它是否导致 Loss Spike 和 μP 跨宽度迁移失败。

目前第一、二步已有可运行代码及 Mac 测试；第三步的研究比较列在本文末尾，**尚未实现训练干预和 μP 模型族**。这一版不会用相关性或单步结果冒充第三步。原 `causal` 入口是上一版的 12 次前向诊断，原 512 步与 α 结果保留为历史结果。

## 1. 用户已选定的工程尺度

从原完整检查点 X512 恢复 AdamW、数据游标和学习率日程，正常完成 X512→X513 一次更新。对每个执行实现分别记录旧支持集 A0：

| 读数 | 参数 | 全网路由 |
|---|---|---|
| L0 | X512 | 正常前向首次记录 A0 |
| L1 | X513 | 正常重选 |
| L10 | X513 | 每层沿用 A0，在本路径当前输入上重新计算门权重与专家输出 |

定义 `U = L10 − L0`、`V = L1 − L10`、`T = U + V = L1 − L0`。

**工程尺度为 U<0、V>0、T>0 同时成立**：连续反事实原本改善任务损失，路由增损却超过该收益，使整步任务损失反而上升。使用同一批文档和同一组重采样计算三项，直接对 T 求区间；不用两个独立区间相减，也不在 U 接近零时用 V/|U| 作主判断。

同时给出绝对 nats/有效 token，以及 `exp(效应)−1` 对应的相对困惑度变化。U 是规定反事实的即时收益，不是已经证明能通过某种训练方法兑现的收益。

分析区分三种情况：三个符号得到同时区间支持；U 有收益且 T 的整个区间仍为负、从而排除本次的完全抵消；其余情况尚未分辨。若连续项本身没有收益，则明确说明该更新没有提供所选尺度的收益基准。区间跨零不会被写成无效应。

## 2. 先把主要比较做成可读的配对实验

每个实现每条输入做 4 组真实执行：旧状态 `N0 → 同支持集空干预`；新状态交替 `N1 → 同支持集空干预 → F1` 与 `F1 → N1 → 同支持集空干预`。所有 F1 使用该实现首次 N0 的 A0。空干预使用紧邻自然前向刚刚记录的支持集，因此只改变调用干预接口这件事。

所有主前向使用相同观察回调，回调只复制选定三层的张量；专家并集参考计算在主前向返回后执行。每次前向重放同一 Python、NumPy、Torch、CUDA 和 Megatron RNG tracker 状态，结束后恢复训练 RNG 和 train/eval 状态。参数照常训练。没有指标阈值控制运行、参数冻结或自动更换精度。

每种实现先完成全部主输入的更新后比较，立即写入 `task/groups.npz` 和 `task/summary.json`，然后才执行该实现的方向部分。用于方向比较的少量中间表示保留在 CPU；第一步摘要不会等全部随机方向结束才保存。两种实现仍依次执行，BF16 主结果最先取得。

分别报告 BF16 原生执行和 IEEE FP32 参考，各自使用各自的 A0。空干预只描述观察到的接口执行差，**不是所有不同支持集路径偏差的统一上界**。重复的差异也不能通过能量相减消除。统计符号即使清楚，也必须结合执行对照解释；FP32 阳性不能直接替代原生训练中的损害证据。

## 3. 方向比较改成同一个起点上的正向注入

在 X513 自然前向的第 ℓ 层捕获实际 router 输入 h 和专家输出相加前的残差 r。在同一个 h、同一个当前参数下，用旧、新支持集的专家并集参考计算两个本层输出。按执行输出 dtype 舍入后相加，得到 `b = r + F_old(h)`、`a = r + F_new(h)`，并定义实际可表示的 `D = a − b`。

后续网络直接从该层之后接续，因此所有比较共享已捕获的前缀；后续路由正常重新选择，损失覆盖整条序列的全部有效预测位置。

| 条件 | 后续网络的输入 | 读数 |
|---|---|---|
| 共同起点 | b | Lb |
| 真实方向 | b + D | Lroute |
| 随机方向 | b + R、b − R | Lrandom+、Lrandom− |
| 原生表示对照 | r + 本次实际 MoE 输出 | Lobserved |

R 是逐 token 的各向同性 Gaussian 方向，在 FP64 中缩放到该 token 的 `||D||`。D 为零的位置注入零，padding 不注入。8 个 Gaussian 抽样各有正负两侧；先平均同一抽样的正负损失，**正负号不算 16 个独立随机方向**。各真实执行重用相同随机方向，以分离方向抽样与执行变化。所有条件的顺序随执行重复打乱，EP 各 rank 使用同一个顺序。

主比较 `specificity = (Lroute−Lb) − (mean(Lrandom±)−Lb)`，正值才表示真实方向更危险。它纠正了旧版“从自然新输出减去 D”与随机扰动直接比较时的方向问题。各层的局部效果不相加冒充全网 V。

BF16 注入时 `b + R` 再次舍入，**实际范数不保证严格等于 D 的范数**。逐 token 保存实际能量、目标能量、绝对偏差，报告汇总偏差比例。必须结合这些数据判断同范数近似是否足以解释该实现的比较。FP32 也保留相同记录，不用名义精度代替实测。

另外报告 `Lobserved−Lroute`（本层参考重建与原生输出的差）和 `Lobserved−完整自然前向损失`（后缀接续差）。这些对照用于识别当前比较的执行局限，不构成普遍误差界。

## 4. 当前计算分配与分辨率

配置位于 [engineering_chain.yaml](../experiments/engineering_chain.yaml)：

| 工作 | 当前分配 |
|---|---|
| 真正训练 | 1 个 optimizer step |
| 全网主比较 | 原测量集 1,024 条输入，4 次真实执行 |
| 方向比较 | 原始序号前 256 条输入；第 1、24、48 层；2 次执行；8 个 Gaussian 正负对 |
| 精度实现 | BF16 execution 与 FP32 reference 分别测量 |
| 统计重采样 | 2,000 次；文档、执行重复、Gaussian 抽样三个轴 |

主比较一共 **40 次完整测量集前向**，不是 40 个 optimizer step。方向部分每个实现、每层、每条输入另做 38 次后缀前向，共 58,368 次单序列后缀调用；末层只执行最终归一化、输出头和 loss。`--print-config` 给出工作量，不能将这些调用数直接当成时长。Slurm 时间仍由本地提交参数决定，没有根据旧作业时长声称本轮必定能在某个时限内完成。

1,024 条主输入保留原分布，256 条方向输入按原序号选择，不只保留完整长度文本。正式 64 rank 配置下，主输入数与方向输入数取 64 的倍数，并使方向输入数不超过主输入数，保证参与 EP 的调用对齐。这是该数据并行分配方式的使用条件，程序不增加前置审查链。

**这些数量是显式的首轮计算分配，不是已经论证能发现工程效应的样本数。** 原 X512 的 V 区间半宽约 1.35×10⁻⁴，按正态近似换算，配合三个符号的多重比较，旧方差下 80% 功效对应的可检测量约 2.2×10⁻⁴ nats/token，大于约 9.9×10⁻⁵ 的连续收益。不能声称重复使用这 1,024 条输入就天然足够。

这次真正改变的是主要比较的调用对称性、同支持集对照和固定前缀的方向比较；其余方差仍需实际测量。新报告提供：

- 文档按有效 token 数加权，合并同一文档的所有序列与 rank；执行和方向取均值，不乘进独立 token 数。
- 主问题的 U、V、T 使用 Bonferroni 同时区间；specificity 在三个预先列出的层之间校正。
- 分别报告只重采样文档、只重采样执行、只重采样 Gaussian 组的标准误，以及交叉重采样区间。
- 给出当前方差下的正态近似 MDE，和以本步连续收益为参考的单轴样本数投影。投影只表示某个分量按独立新增样本缩小的近似，不包含路径偏差；其他分量不会随之自动消失。观测分量为零时不推导零次执行的方案。

如果本次仍分不清，报告应如实指出是哪个比较、哪个不确定性分量和多大的剩余区间。扩大方向数或 token 数不能代替解决未知执行偏差。这些统计只影响研究解释，不自动取消作业、跳过输入或改变训练。

## 6. 第三步必须是另外一组训练因果比较

第一、二步改变的只是当次评估。第三步要研究的是：干预路由跳变后，实际训练风险和跨宽度超参表现是否改善。需要比较下列训练分支，而不是继续加密 α 曲线：

| 分支 | 用途 |
|---|---|
| 原训练算法 | 记录原始损失、spike、梯度和验证表现 |
| 明确定义的路由针对性干预 | 改变已被第一、二步识别的有害贡献，并记录实际改变了什么 |
| 同计算量的空干预 | 分离多一次计算、执行路径或随机状态变化的影响 |
| 同等更新/输出变化量的普通干预 | 分离一般减小步长、平滑或扰动幅度带来的收益 |

每个种子内分支从相同完整优化器状态、相同数据游标和 RNG 出发；分支之间真实训练并独立保存状态。各参数正常更新，不能把不更新 router 或全模型当成这项验证。干预的精确定义应由第一、二步识别出的机制确定，并单独实现；当前代码没有暗中选一个新正则器或更小学习率作为答案。

**Loss Spike：** 先用独立校准区段定义相对局部趋势的超额损失及 spike 事件规则，再在保留区段比较每 token 的事件率、超额损失面积、极端梯度与恢复时长。所有预定训练分支都计入，包括出现数值失败或未完成的分支。用相同种子的配对差估计影响，不只展示某条最好看的曲线。路由测量须在事件前提供预测增益；针对性干预减少 spike 且普通对照不能解释，才支持特定训练条件下的因果贡献。第一步的平均增损不能替代这项时序证据。

**μP 迁移：** 使用同一模型族的至少两个宽度，明确每类参数的初始化、学习率和读出缩放；专家数、Top-K、数据预算、序列长度、优化器及其他配方保持可比较。已有一个 Qwen3 宽度的 X512 不能提供这组状态，任意两个不同预训练模型也不是受控宽度比较。

在小宽度上用独立验证集选基础学习率，再将该基础学习率按同一 μP 规则直接用于大宽度。另在大宽度运行同一候选学习率网格，以独立验证集选大宽度参照；两者最终在未参与选择的保留数据上比较迁移差距。各干预分支重复这个过程，并报告学习率排序、最佳区间、spike 风险和相同预算下的任务损失。一般的学习率敏感性不能冒充 μP 迁移失败。

只有路由针对性干预同时降低所识别的路由损害，并改善这些配对训练结果，且空干预、普通干预及连续更新差异不足以解释改善，才支持其为该模型族的因果来源之一。“根因”还要求说明能解释多少失败、剩余失败有哪些；一次方向比较阳性或阴性都不能全局裁决。

第三步的宽度状态、干预算法和训练方差现在均未取得，因此本次不虚构一份保证功效的多宽度 GPU 作业矩阵。当前交付的是第一、二步的可运行比较和第三步必须保留的因果目标，报告会明确标记实际完成的范围。
