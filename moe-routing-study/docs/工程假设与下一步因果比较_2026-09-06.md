# 工程假设与下一步因果比较

本文保留上一版诊断的定义与历史讨论。当前工程尺度已由用户选定为“路由增损抵消一步连续收益”，第一、二步改用 `moe_study.engineering`；当前计算分配、方向比较和第三步研究目标见[三步工程实验链](engineering_chain.md)，以该文为本次运行说明。

日期：2026-09-06。依据：本轮原始测量、已有结果报告，以及新增的独立复算文档。一次更新补测已实现为独立入口 `python -m moe_study.causal`，完成 Mac 软件验证，尚未执行新的 H20 作业。运行命令见[补测运行说明](causal_run.md)。

**这轮完成了存在性和首层局部尺度验证；“真实路由跳变是值得修复的训练问题”这一核心工程假设没有得到支持。深层执行差尚未分离，因此也不能把它作为干净的否定结果。现有证据不足以支持进入新方法训练。**

此前把结论重点放在“已有实质机制证据”，弱化了研究决策真正需要的任务效应与工程量级。下一步的价值取决于能否提高这个问题的判别能力，而不是再增加层数、α 点或轨迹长度。

## 1. 新材料改变了什么

| 问题 | 当前证据 | 对研究决策的含义 |
|---|---|---|
| 硬路由切换及局部输出差是否存在 | 已观测到 | 完成存在性测量 |
| 首层是否呈现平方根尺度机制 | 七个非零 α 点上，切换概率指数 0.9379、条件能量指数 0.0246、路由 RMS 指数 0.4812；其余更新 RMS 指数 0.9994 | 机制解释得到加强，仍是有限网格与单次真实方向的证据 |
| 实际步长下是否增损 | 四次大样本 V 区间全部跨零；FP32 α=1 也跨零 | 没有分辨出平均任务损害 |
| 真实干预是否比同范数随机方向更危险 | 配对差区间跨零 | 没有支持方向特殊性 |
| 深层观测能否归因于参数更新 | 第 512 步有 42/48 层的重复能量 / T execution 超过 0.8 | 数值执行来源仍影响归因 |
| 稳定性、学习率敏感性、μP 迁移是否受到影响 | 没有独立训练比较、学习率比较或宽度比较 | 本轮没有检验 |

新增的指数分解来自 `J = p × Q̄`，其中 p 是切换比例，Q̄ 是切换条件下的平均能量。它说明首层 J 的尺度主要来自事件发生率；全网格拟合不是新增的置信区间，也不是 α→0 定理的实验证明。

第 24、48 层的 92.8%、86.2% 是“同状态重复输出差能量 / 一次更新总输出差能量”。不能写成“J 中有这么多百分比是噪声”，也不能相减得到真实 J。观测到的差既可能涉及浮点归约和上游路由放大，也可能涉及测量执行方式；当前数据没有唯一定位其来源。

新增独立分析只取得了 `report.zip`，因此其“缺少源码和文档组原始记录”是对该压缩包的说明。本地完整分析目录已有这些文件，可以继续做现有数据分析；缺失的完整逐 token margin、S/C/T 联合记录则无法补算恢复。

## 2. 同范数的两个参数更新，不足以构成严格对照

设两个方向分别为 Δθₛ 和 Δθ꜀，前者发生切换，后者不切换。即使

\[
\|\Delta\theta_s\|=\|\Delta\theta_c\|,
\]

也没有保证它们的梯度投影、曲率、参数组分配和连续输出变化相同。在同一个光滑分支内就可能有

\[
L(\theta+\Delta\theta_s)-L(\theta+\Delta\theta_c)
\approx g^\top(\Delta\theta_s-\Delta\theta_c)
+\tfrac12\bigl(\Delta\theta_s^\top H\Delta\theta_s
-\Delta\theta_c^\top H\Delta\theta_c\bigr)\ne0.
\]

跨边界时还要精确计算分支差，不能用这段局部展开取代它。通过投影构造“不切换更新”尤其会系统性改变更新方向；由此得到的损失差同时包含方向改变和路由改变。

**主比较应保留完全相同的一次真实参数更新，只改变更新后前向是否沿用更新前的支持集。** 两个评估条件的参数、更新范数和优化器来源因此完全相同。它是明确的前向路由干预，不是两条不同的训练算法。

同范数不切换方向可以作为后续方向对照；它回答“这两个方向哪个更有害”，不能单独证明“不连续本身”造成了额外损害。原研究文档第 05 篇第 8–9 节已经指出这一限制。

## 3. 一次真实更新，三个明确的前向条件

恢复现有 X512 的完整训练状态，保持原优化器、学习率、数据游标与训练 batch，正常执行一次更新得到 X513。旧端点使用原完整检查点，新端点保存各 rank 持有的精确 FP32 主参数分片和执行 dtype；主测量直接使用原生执行权重。现有导出包只有检查点元数据，实际恢复仍使用原存储中的完整检查点；本地不能用这些摘要恢复权重。

本轮不要求重建已经轮换掉的 X511。X512→X513 是新的一步，不把它写成原 511→512 的精确重放。FP32 端点直接读取对应主参数；不要靠插值算式在 α=1 重建端点，以免额外舍入改变所比较的状态。

对每一种评估实现 p，分别定义自身的旧支持集 A₀ᵖ(x)：

| 条件 | 参数状态 | 路由方式 | 读数 |
|---|---|---|---|
| N₀ | X512 | 该实现正常选路由 | L₀ |
| N₁ | X513 | 该实现正常选路由 | L₁ |
| F₁ | X513 | 全层沿用 N₀ 首次前向记录的支持集 | L₁∣₀ |

F₁ 每层使用它自身传播到该层的当前输入、X513 的 router 和专家权重，在旧支持集内重算门权重并归一化。不能复用旧专家输出、旧门权重或 N₁ 的中间隐藏状态。前面层的干预沿注意力和残差路径继续传播到后面层，最终重新计算任务损失。

主效应为

\[
V=L_1-L_{1|0};\qquad U=L_{1|0}-L_0.
\]

V>0 表示这一步的自然重选路由，比同一更新后参数采用旧支持集的评估更有害。**这就是本轮已经测过的 V。下一轮的新工作是改善其执行可比性、独立重复和误差定位，不能把相同指标重新命名成新因果证据。**

这个干预包括完整支持集改变、门权重重新分配和下游传播，回答特定软件干预的即时效果。它并不单独识别数学上的“纯跳跃项”，也不等同于采用旧支持集训练后的长期收益。参数仍全部正常更新，旧支持集仅用于这一组评估。

## 4. 已实现的执行改动及剩余限制

原测量入口有三处与这次问题直接相关。新的独立补测入口逐项调整如下，历史 α 入口仍保留原测量定义。

1. `PairedMeasurement.finish()` 的本层回调中会再调用原生 `execution_route()`，复用当前模块的 dispatcher，并进行本层高精度重算。自然路径、重复路径和全网旧支持集路径承载的额外运算不同。新入口的主前向回调只捕获数据，局部专家重放放到主前向结束之后；不在主前向中嵌套调用同一个 dispatcher。现有源码能确认原调用差异，但不能仅凭它断定这是重复差的根因。
2. 原 `preserve_rng()` 包住一整段测量，并未在每个配对前向前恢复同一个状态。当前 dropout 为零，不能据此归咎于 dropout；新入口在每个独立前向前恢复相同的 Python、NumPy、CPU/CUDA 与 Megatron RNG tracker 状态，并在评估后恢复训练状态。
3. α 基线的 `capture(repeat=False)` 产生了复用结果的零重复差。新入口每次重复都实际执行网络，写入独立的重复编号，不把未测值写成零误差。

两个实现分别是原生 BF16 执行和现有 IEEE FP32 全网参考。每个实现内部保持相同的样本顺序、batch 形状、rank 分配、通信组、运算配置与观察回调。各实现使用自己的 A₀，分别报告结果；不能把 BF16 旧支持集直接用于定义 FP32 的旧状态。

FP32 只说明算术精度，不能预先保证整网重复前向一致。原生 BF16 的重复差也不能靠恢复 RNG 自动消失。官方 PyTorch 文档说明 CUDA `scatter_add_` 可能不确定；对应版本的 Megatron 非融合 `unpermute` 含有该归约路径。当前配置关闭 permute fusion，因此这是值得定位的候选来源，仍需实际执行证据确认。见 [PyTorch 2.9 scatter_add_](https://docs.pytorch.org/docs/2.9/generated/torch.Tensor.scatter_add_.html) 与 [Megatron Core 0.15 源码](https://github.com/NVIDIA/Megatron-LM/blob/core_v0.15.0/megatron/core/transformer/moe/moe_utils.py)。

诊断记录让同状态前向的分歧可按层定位：归一化前输入差、router 输入差、router 分数差、所选专家和专家聚合输出差。对少量同输入本层重放，用显式专家顺序累加的 FP32 参考与原生输出比较。目前未捕获原生 dispatcher 内每个专家归约前的向量，因而这些记录不能单独确定某个 CUDA 内核是根因。若之后为了测量修改 BF16 归约实现，应命名为单独的受控执行路径，保留它与原生路径的端点差；不能把修改后的结果当成原生执行已经准确。

这里的改动目标是去掉已知的执行不对称，并直接记录剩余重复差。它不保证下次一定得到低底噪；也不使用全局“开启确定性，否则拒绝运行”的逻辑。

## 5. 有限、具体的补测规模

只做一次 optimizer step。主样本继续使用已有的 1,024 条输入、891,233 个有效预测位置、867 个文档组，以便与已有结果比较。

每个实现执行 N₀、N₁、F₁ 各两次真实前向：合计 **12 次完整测量集前向**，即原生 BF16 六次、FP32 六次。这里一次指遍历整个测量集，不是一条序列。N₀ 首次记录的 A₀ 用于该实现全部 F₁；另一次 N₀ 的路由差独立报告，不悄悄替换反事实定义。更新后第一次按 N₁→F₁ 执行，第二次按 F₁→N₁ 执行。

重复仅用于观察本次执行差，两个重复不能充分估计执行方差或证明未来可重复。报告保留两个 V、各条件的重复差和重复支持集差，不能把重复次数乘进独立文档数。

详细中间量只在已有 157 条完整长度序列中，按原顺序取前 64 条记录，覆盖所有层。测量顺序将这 64 条排到最前面，再分给各 rank，原始序列 ID 保留；所以它与上一轮的 rank 分配可能不同，各配对条件内部完全一致。这个诊断子集与主样本结果分开报告。所有 rank 保持一致的调用次数；当前每 rank 独立序列并带 EP 集合通信的实现，不使用让部分 rank 空闲的小于 64 条输入的直接切片。

这一轮不增加 α 扫描、随机方向矩阵或新的 512 步训练。两种执行实现服务于同一个效应比较。已有 C 段混合了大量本层参考重放，不能据其总时长准确预测本方案耗时；实际记录加载、一步训练、各前向和局部诊断的时间即可。

## 6. 主结果与需要保存的内容

主结果是每个实现、每个重复的 V，单位 nats/有效 token。文档组配对重采样时，所有比较共同抽取文档 ID，并计算 `所有抽中文档的差值之和 / 有效位置之和`。保留点估计、输入抽样区间及观察到的执行重复差，三者分开解释。

平均数之外，保存逐文档和逐有效 token 的有害与有利贡献。令 vᵢ 为配对损失差，同时给出 `mean(max(vᵢ, 0))` 与 `mean(max(-vᵢ, 0))`，以及文档级损失差分位数。正负部分在纯执行噪声下也可能都非零，应同时画出重复差的对应分布，不能把正尾部直接当作损害证据。

logits 辅助回答输出分布是否改变：报告自然新路由与旧支持集路径之间的逐位置 KL，以及减去各自词表均值后的 logits RMS。纯 logits 常数平移不改变 softmax，因此不用未中心化 RMS 单独解释任务影响。全词表值按位置分块比较后保存标量，不落盘所有 logits。KL 或 RMS 非零也不能替代增损证据。

保存范围如下：

| 文件内容 | 范围 | 用途 |
|---|---|---|
| `effects.json`、`*/network/groups.jsonl` | 全部主样本，各实现、条件、重复编号 | V/U/总差、重复差、文档组配对区间 |
| `*/network/tokens.npz` | 主样本的有效位置、文档/序列/位置映射、各条件损失、KL 与中心化 logits RMS | 正负贡献、尾部、后续 Mac 分析 |
| `*/diagnostics/sequence_*.npz` | 64 条诊断序列、48 层 | 旧/新/重复支持集、8/9 margin、最大分数差、router 输入与归一化前残差流能量、本层参考 J、逐层分歧定位 |
| 两端参数读数与训练状态引用 | 对应 X512 和 X513 | 精确说明比较的参数来源，保留重放所需端点 |
| 运行配置与分段计时 | 本次实际执行 | 区分实现、精度、采样和执行代价 |

旧指标 `r_h` 的分母是 post-layernorm router 输入能量。新入口另外采集专家输出加入前的残差流能量，保存为 `N1_residual_energy` 等联合标量；后续 residual exposure 可用本层 J 与该分母计算，不能沿用旧 `r_h` 标签作替代。程序保存联合标量，不生成大规模逐专家向量全集。

## 7. 这次比较能支持怎样的决定

| 观察 | 可以采用的结论 |
|---|---|
| 原生执行重复差小，V 稳定为正，并有足够工程量级 | 支持这一步、这组输入上的旧支持集反事实更优；为方法研究提供直接任务证据，仍未证明长期收益 |
| FP32 得到效应，原生 BF16 仍被重复差覆盖 | 参考执行中的任务效应得到支持，原生训练中的量级仍未分清 |
| V 接近零，区间足够窄，重复差也小 | 可以排除本测量条件下大于所报告上限的即时平均损害 |
| 区间跨零且宽，或重复差仍同阶 | 当前设计仍未分辨；可据投入收益停止继续投入，但不能写成问题已被证伪 |

“没有显著差异”不等于“已经证明没有工程量级差异”。如果需要具体的无重要损害结论，应给出区间允许的增损上限，或相对一个有实际意义的损失尺度讨论它。目前没有给定统一的工程阈值，因此不凭空设定通过值，也不使用显著性阈值控制程序执行。

例如，本轮 FP32 α=1 的 V 区间为 [−1.168×10⁻⁵, 1.145×10⁻⁴] nats/token。它仍允许约 1.145×10⁻⁴ 的即时平均增损；它是否重要，需要与目标任务和使用成本关联。不能把这个单步数乘以 512，预测长期累计损害。

同样，即使下一次即时平均 V 很小，也不能直接排除罕见 loss spike、梯度差、学习率敏感性或跨宽度迁移问题。可以把“一次补测仍无任务证据则停止这条方法线”作为资源决策；科学结论则限定为本次实际测到的效应和范围。
