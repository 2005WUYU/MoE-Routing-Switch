## 3. 平方根斜率怎样得到，为什么不能过度解释

取 r 在 [−1,1] 均匀分布，更新后 r−α。两个常数专家分别为 +1 与 −1。切换区间为 (0,α)，其概率 α/2，每次输出差平方为 4，所以 J=2α。另加一个所有样本相同的连续偏移 α，使连续项能量为 α²。

本次扫描 α 从 2⁻¹² 到 2⁻⁴，采用二的幂网格。区间端点与积分网格对齐，使切换计数恰好对应闭式值。发生率与 RMS 斜率达到接近机器精度的 1 和 1/2 是这个构造的数值一致性，**不是在真实 MoE 中发现了同样精确的经验规律**。

这一例子用于检查定义、代码、单侧系数与交叉项。它不检验真实优化器方向、语言输入分布、专家分化或宽度变化。

## 4. ReLU 对照检验的具体对象

取输出 max(r,0)，分数平移为 r+α。只在新激活而旧时未激活的区间 (−α,0) 上，支持变化项为 r+α，故其平方积分为 α³/6，RMS 阶为 α的3/2次方。

旧时已激活的样本仍有普通连续变化，因此完整输出均方为 α²/2+α³/6。不能把支持变化项的 3/2 阶当成全部输出 RMS 的阶。它只用于验证“支持发生改变”和“函数存在有限跳变”不是同一个事件。

## 5. 增损构造与有限 batch 结果

第 04 篇给出函数 fθ(x)=θ+sign(x−θ)，目标 2x+0.1，学习率 0.25。总体平均分支梯度为 −0.2，更新 θ=0.05。闭式风险变化分别是固定路由 −0.0075 与真实重新路由 +0.0025。

数值网格在 θ=0.05 的边界处不完全对齐，实际积分得到 0.002499771119，误差处于脚本声明的积分容差内，未通过改写解析目标来消除误差。

对 B=16 的有限 batch SGD，第 04 篇证明真实期望风险变化为 0.0025+1/(12B)，固定路由为 −0.0075+1/(12B)。脚本通过积分核对单样本梯度的一、二阶矩，再代入独立 batch 平均的方差，得到表中结果。**这里没有伪装成执行了一次真实训练：有限 batch 部分检验的是解析矩与期望值。**

这一构造使用路由阈值与共享连续分支共用参数，证明“这种优化损害可能存在”。其结构并不等于现代 LLM，不能用来估计现代模型中的发生频率。

## 6. 复现与检查方式

将文件夹整体解压，进入目录后运行：

```bash
python 验证代码/verify_moe.py
```

依赖只有 NumPy。已有环境需要记录实际版本；本次使用版本写在第 1 节。结果默认写入 `数值结果/`，会覆盖其中同名结果文件。需要保留原结果时，指定独立目录：

```bash
python 验证代码/verify_moe.py --output-dir 重新检验结果
```

脚本允许调整 `--grid-power`，范围 16—23，默认 20。代码中的解析期望、误差容差与实际数值均写入 JSON。修改样本规模后，ReLU 的离散积分误差可能改变，脚本已按最小跨界格子数设置相应容差。

浮点舍入在不同环境可能出现末位变化；应检查公式误差与声明容差，而非要求 JSON 字节完全相同。文件哈希用于识别本次交付版本，不是跨平台数值一致性的保证。
