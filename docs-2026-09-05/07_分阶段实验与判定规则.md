# 从最小可证伪实验到跨宽度确认

本篇是待执行的真实模型实验方案。用户提供的是研究材料，没有提供训练 checkpoint、日志、目标代码库或可执行集群环境。本次已经完成的只有第 08 篇所列解析和数值检验，不能把下面的配置表视为已经跑出的结果。

## 1. 总体次序与每一步能回答的问题

| 阶段 | 要回答的问题 | 进入下一步所需证据 | 不能越过的限制 |
|---|---|---|---|
| E0 测量验收 | 工具是否实现了定义 | 独立参照、数值底噪、梯度与分布式测试通过 | 恒等式通过不够 |
| E1 现象与假设 | 真实更新是否跨界；局部理论条件是否适用 | 足够事件、固定编号、分层分解及实际步长统计 | 不强求每层都出现 1/2 斜率 |
| E2 任务影响 | 真实步长的路由差是否产生实际影响 | 精确任务干预、量级和不确定区间 | J 大不直接等于损害 |
| E3 小规模干预 | 现有或候选方法是否改善目标问题 | 配对算法比较、质量与代价不过度恶化 | 不能只比较最低 J |
| E4 宽度迁移 | 小模型规则能否迁移到未调参宽度 | 完整或预定局部 LR 曲线、独立测试 regret | 单个大模型成功不等于普遍迁移 |
| E5 现代工程扩展 | 结论是否覆盖不同路由、负载和优化器 | 对每条扩展重新检验相关假设 | 不把不同尺度路径合并拟合 |

若某阶段证据不足，输出相应范围内的结果和误差界；这不要求强行继续方法训练，也不意味着理论问题不能再研究。

## 2. 首先建立两个清楚区分的模型实现

### 2.1 机制参考实现

用于测量验证的小型 decoder-only Transformer，可从 6 层、宽度 256 和 512、每两层一个 MoE、M=8、K=2 开始。选定一种明确的门规则，例如 selected softmax normalization；关闭 token drop 和随机 dropout，使用 FP32 参考前向。专家使用便于核对的线性层或 MLP，随后再换 SwiGLU。

这只是机制测试模型。使用现代激活或重新归一化门后，不能称为严格复现某篇使用不同公式的论文。最终应让生产 kernel 与参考实现共享模型定义，但不共享全部内部计算逻辑。

### 2.2 参数化复现实现

固定 M、K 扩宽时，优先单独复现 R03 的 MoE 公式和参数化。该论文写出的专家为两层 ReLU MLP，门为 softmax 后 Top-K 截取；在复现时应按该公式处理，不悄悄改成 selected normalization。

下表给出其推导中采用的物理权重参数化形式，所有量都是尺度阶而非可直接使用的绝对数。它与另一些“标准初始化加前向乘子”的写法不能在实现中混用。

| 参数类型 | 初始化方差阶 | Adam 参数组学习率阶 | 本项目核对点 |
|---|---:|---:|---|
| 固定输入维度到增长维度的输入权重 | \(1/d_{\rm in}\) | 常数 | embedding 与输出是否错误绑定 |
| 两端维度都增长的隐藏权重 | \(1/d_{\rm in}\) | \(1/d_{\rm in}\) | attention、专家输入和输出矩阵的 fan-in 分别计算 |
| 增长维度到固定维度的输出权重 | \(1/d_{\rm in}^2\) | \(1/d_{\rm in}\) | 固定专家数下 Router 属于该类 |

来源为 R03 Table 2 及第 3.4 节。它不单独保证任意实际 AdamW 实现具有完全相同轨迹。Adam epsilon、weight decay、参数重缩放和前向乘子都会影响真实更新，须记录实际 update 并检查。

以基础 fan-in \(d_{\rm in,0}\) 为参照，可将上述阶写成实际比例：隐藏权重方差乘 \(d_{\rm in,0}/d_{\rm in}\)，输出权重方差乘其平方；对应隐藏、输出参数组学习率均乘该比例；输入组学习率不变。基础常数由小模型决定。方差比例不是标准差比例，后者要开平方。

在实验清单中逐个列出参数名、shape、fan-in、初始化标准差、前向乘子、组学习率、epsilon、weight decay，禁止只写一个 `mup=true`。

## 3. E0：测量工具验收

第 08 篇的 CPU 测试提供起点。接入训练代码后需增加四类检查。

首先，实际前向与指定相同路由的重放匹配；关闭更新时重复测量不得凭空产生路由差。其次，生产稀疏计算与独立全专家求和参照匹配。再次，辅助损失的 Router 和 h 梯度应严格为零，而专家参数能收到预期梯度。最后，对单卡、跨 rank 专家、容量 mask 和 token 排序做一致性测试。

可以固定 8—32 个序列进行这一阶段，目的只是正确性，不估计真实分布。每个不支持的路由机制应明确报错。验收失败时，不运行昂贵的规模训练。

交付物是测试代码、预期值、实际误差、环境版本、失败注入记录和生产实现对照，而非只有“全部通过”的文字。

## 4. E1：先测真实一步，再检查渐近行为

### 4.1 固定记录窗口

至少保存初始化后、warmup 中、峰值学习率附近、稳定学习阶段和衰减阶段的连续短窗口。不要只挑已经发生尖峰的步；使用预定时间抽样，事件后额外保存的窗口单独标注。

每个窗口保存完整 \(\mathcal X_t,\mathcal X_{t+1}\)，以及固定输入前向的层输入、完整或足够候选分数、旧新专家 id、容量状态、门权重和输出。数据、tokenizer、序列位置必须可追溯。

### 4.2 每一步先测实际 \(\alpha=1\)

计算总体 support change 率、每个 token 更换专家数、单个 K/K+1 交换比例、实际新专家的旧排名、S/J/C、残差归一化差及完整任务损失干预。增加 uniform probe 序列直到主要量的区间宽度达到预设要求，不能只增加同一序列中的 token 来假装增加独立样本。

要比较的是实际工作步长。高学习率、放大更新或随机扰动可以作为压力测试，但必须独立标注，不能拿人为制造的失败替代真实训练问题。

### 4.3 再做更新方向缩放

可从

\[
\alpha\in\{2^{-10},2^{-9},\ldots,2^{-1},1\}
\]

开始，视事件数扩展区间；\(\alpha=2\) 仅作邻近压力测试。每个点从同一个旧状态构造，分别测完整实际网络和全部上游路由固定的路径。

检查旧专家对的带符号 margin、速度近似误差、多边界事件率和数值翻转。只有满足第 03 篇的条件并具有足够统计功效，才将平方根斜率作为理论检验。

**不能使用的否定规则。** “某层斜率不是 1/2，所以问题不存在”不成立：可能没有连续密度、边界输出本来相等、上游发生跳变、样本阈值太高，或当前扰动区间不够小。先检验假设，再解释斜率。

## 5. E2：任务影响与机制区分

对预定 checkpoint 的总体 probe，在更新后真实输入处比较旧、新本层 support，测完整 sequence 平均交叉熵变化。分别固定和放开后续路由，记录两种效果。

增加与真实差同范数的随机扰动和连续更新方向扰动。分析大 J 但损失差小的情况，以及 J 小而损失差大的情况。可计算梯度投影及 GGN 近似，但必须用精确损失比较校准。

只对少数层作单层干预，再选择代表性 checkpoint 逐层释放旧路由，检查深层相互作用与顺序依赖。不要把各层单独干预效果相加当作全部路由效应；只有按顺序完整运行的望远镜求和具有相应精确分解意义。

### 5.1 该阶段的判断

若在真实步长下能证明影响上界低于预定实际重要阈值，可以报告该模型族中此机制可忽略。若区间太宽，应报告证据不足。若出现稳定的有害反事实损失，并能排除数值、容量和负载变化，才有充分理由投入对应训练干预。

不需要要求所有层都显著。少数层或特定训练阶段可能是合理、清楚的适用范围，但该范围应在探索后用独立 run 确认。

## 6. E3：先用小规模配对实验筛选干预

首轮可选四个配置：原强基线；第 06 篇的专家侧边界一致性；可实现的连续化强对照；作用于 Router 更新的对照。共享专家、相同初始化或数值精度按 E2 发现的机制补入，不先做全组合。

在一个可承受宽度上，比较接近基线优选的学习率，以及预先用独立试验确定的较高但仍有实际意义的学习率。每组 3 个配对 seed 可作为探索起点，形成 \(4\times2\times3=24\) 条轨迹；这不是最终统计功效承诺。

边界系数 β 的候选先根据第 06 篇的实际辅助输出响应挑选，覆盖弱、中、强作用；必须保留 β=0。不要仅按辅助梯度范数与主梯度范数的比例断言跨宽度公平。

### 6.1 配对方式

相同模型定义下使用相同初始参数、数据顺序和 RNG。改变模型结构时，共用数据顺序和可以合理对应的初始随机变量，但不能声称不同参数形状实现了逐参数相同初始化。

从 checkpoint 开始的短分支试验与从头训练的长期试验分开。前者识别局部作用，后者验证方法累积后是否仍有用。训练长度应预先锁定，以免选择收益最大的停止点。

### 6.2 筛选标准

优先考虑真实有害损失变化下降、最终验证损失改善、发散或恢复指标改善且开销可接受的配置。J 下降只是机制证据之一。也保留至少一个重要解耦例子，例如 J 较大但迁移好，或 J 较小但任务较差。

训练 wall-clock、有效 tokens/s、总专家 forward/backward、通信量和峰值显存均须报告。相同 token 数与相同计算预算是两种比较，主结论应说明使用哪一种。

## 7. E4：学习率与 β 的迁移检验

### 7.1 主尺度路径

固定深度、M=8、K=2、归一化、门规则、每步 token 数、数据次序与训练 token 总量，使用

\[
d\in\{256,512,1024,2048\}.
\]

专家中间维度按同一比例增长。若最大宽度无法运行，可在执行前替换为可承受的四个递增宽度，保留至少两个未参与调参的宽度；不能观察结果后只保留成功宽度。

四个宽度既用于检查趋势，也不足以数学证明无限宽结论。需要报告有限范围和外推误差。

### 7.2 学习率扫描与近似 oracle

每种优化器分别建立 base LR，取预定对数网格，例如

\[
\eta\in\eta_0\{1/8,1/4,1/2,1,2,4,8\}.
\]

不同参数化的这个 η 是各自配方的 base LR，不等于所有参数组的实际 LR 相同。记录实际组 LR 和更新。

若最优点落在网格端点，按事先规则向外扩展；如果预算不允许扩展，则只报告“已测网格最优”，不能称全局最优。曲线平坦时，比较可接受学习率区间和 regret，比只比较 argmin 位置更稳定。

### 7.3 严格的数据与宽度留出

训练数据用于模型更新；校准 probe 用于设计方法及概率权重；调参验证集用于选 \(\eta,\beta\)；独立测试集只用于最终迁移损失。用测试集反复挑 β 会破坏验证。

在基础宽度挑选 \((\eta_0^*,\beta_0^*)\)。第二个小宽度最多用于检验或确定预先声明的缩放规律。较大两个宽度不再按最终测试结果修改规律。大宽度自己的近似 oracle 也在调参验证集选出，再统一到独立测试集测差，避免对同一 noisy test loss 取最小带来的偏差。

### 7.4 主报告量

\[
R_{\rm transfer}(d)
=L_{\rm test}(d,\eta_0^*,\beta_0^*)
-L_{\rm test}(d,\eta_d^*,\beta_d^*).
\tag{1}
\]

若采用预先确定的 β 缩放，则第一项替换为相应规则。报告区间、oracle 网格、全部失败 run，并同时报告 loss-vs-LR 曲线、实际辅助响应与目标 J 的尺度变化。

两种方法、四个宽度、七个学习率、三个 seed 是 168 条轨迹，尚不包括 β 搜索。这个数字说明为什么 E4 不能作为第一轮实验。β 搜索另记 \(N_\beta N_\eta N_{\rm seed}\) 的成本，已完成且协议相同的重合运行可以复用，不可重复计算收益却漏记成本。

## 8. E5：按明确路径扩展现代工程配置

### 8.1 固定 K 扩大专家池

固定 d 和 K，令 \(M\in\{8,16,32,64\}\)。主干每步 B 不变时，单专家负载 \(BK/M\) 下降，这本身是优化变化。补充增加 B 或延长训练以匹配专家暴露的实验，可以检查负载解释，但这些操作又改变主干 batch 或训练时长，不能称完全无混杂控制。

### 8.2 固定激活比例

可取 \((M,K)=(8,2),(16,4),(32,8)\)。它与 R04 的某些尺度条件更接近，但聚合专家数、计算量和平均权重变化也需记录。不能与固定 K 结果放在同一个横轴上当作一条规律。

### 8.3 其他工程扩展

selected normalization、sigmoid gate、选择 bias、group routing、capacity、SwiGLU、共享专家、BF16/更低精度和 Muon 分别加入。每加一项，重新检查哪些定理假设改变、哪些日志字段需要扩展。R05、R06、R07 的联合配方按其原适用路径另作强基线，不将各篇局部规则随意混合为一个新“标准 μP”。

不同优化器先分别调整基础学习率并记录真实 update。不能把相同数值 LR 称为同等更新强度，也不能把 AdamW 下的 β 收缩推导直接移给 Muon。

## 9. 预先固定结论与证据门槛

| 假设 | 支持它需要什么 | 否定或限制它需要什么 |
|---|---|---|
| 局部一阶均方机制适用 | 条件诊断通过、分布或连续代理明确、有效区间内系数与斜率一致 | 条件满足且有功效时仍系统不符；或条件不满足，限制适用范围 |
| 真实步长影响重要 | 独立总体 probe 中任务效应超过实际重要阈值 | 对应置信上界低于阈值；不是只看 p 值不显著 |
| 指标提供额外预测力 | 在 run、宽度等留出上，超出现有 norm/logit/load 指标 | 留出改善区间低于预设最低增益 |
| 方法有效 | 随机化配对比较改善任务或稳定结果，并计入开销 | 只降 J、不改善任务，或收益不足以覆盖成本 |
| 新系数可迁移 | 规则提前确定，两个以上未调参宽度的 regret 可接受 | 大宽度需要事后重新搜索，或误差超出预设界限 |

任务阈值用 nats/token、发散概率差、恢复步数或 wall-clock 等可解释单位。原材料中的“J 少于 1%”“Q 降 50%”“loss 不差 1%”可以作为设想，不能直接当作已论证的通用阈值。先估计噪声与实际代价，再锁定主实验门槛。

## 10. 记录与交付文件

每条运行保存配置与代码 commit、环境版本、输入数据哈希、所有参数组、种子、失败状态和训练统计。每个审计事件还应保存 update 前后状态 id、probe id、层、旧新专家集合、固定专家对 margin、门协议、容量协议、S/J/C、残差尺度和精确损失差。

原始记录与汇总分开。只存均值会失去重查尾部、采样偏差和候选遗漏的能力；只存完整张量又可能代价过大，宜对预定代表性窗口保存全量，其余保留可追溯的对象级统计及随机样本。

可执行的任务依赖是：`reference_forward` → `route_replay` → `state_snapshot` → `local/global_audit` → `loss_patch` → `weighted_sampling` → `paired_training` → `transfer_report`。每个模块都应有独立测试，不能把所有功能零散塞进训练循环。

## 11. 预算由实测时间计算，不假定手中硬件

对配置 r，测得正常一步时间 \(t_r\)、训练步数 \(T_r\)、审计次数 \(A_r\) 和每次审计成本 \(a_r\)，总时间预算为

\[
T_{\rm wall}\approx\sum_r(T_rt_r+A_ra_r)+T_{\rm checkpoint}+T_{\rm evaluation}.
\tag{2}
\]

多卡并行需进一步记录实际同时运行数和资源竞争。审计 offload、模型副本及通信可能占显著成本，不能只按多算一个 expert 的 FLOPs 估计。

先测一个最小配置的正确性和速度，再决定阶段规模。优先保留独立确认与强对照，削减无证据支持的全组合搜索，而不是为了覆盖很多配置只跑一个 seed。

## 12. 最终可以产出的三类研究结果

机制结果需要把真实事件、任务影响和受控干预连起来；诊断结果需要证明留出预测增益；否定性结果需要给出指定模型族中的实际影响上界或明确反例。三类都应写清适用范围。

只有局部数学不连续和几张曲线，不足以声称解决现代 MoE 训练稳定性。相反，若已经建立可靠测量并证明某些强配方中该机制并非主要风险，研究也已经回答了原问题的重要部分，无需为了方法形式继续制造不稳定。
